# Source policy

The primary normative and reference sources are MDN Web Docs, web.dev, W3Schools, Sass documentation, Can I Use, and the MDN browser-compat-data project. Each chapter includes links to the relevant source family. The book paraphrases and teaches; it does not reproduce source pages.

### Source cards

:::source-cards
MDN Web Docs|The primary reference for CSS syntax, property definitions, formal value grammars, specifications, and browser-compatibility notes.|https://developer.mozilla.org/en-US/docs/Web/CSS
web.dev|Practical, modern guidance for learning CSS, building resilient interfaces, and applying performance and accessibility principles.|https://web.dev/learn/css
W3Schools|A quick-reference companion for approachable property explanations, syntax reminders, and small runnable examples.|https://www.w3schools.com/css/
Sass|The source for Sass language features, modules, nesting, mixins, functions, and the modern Sass-to-CSS workflow.|https://sass-lang.com/documentation/
Can I Use|A release-time browser-support lookup for CSS and web-platform features across desktop and mobile browsers.|https://caniuse.com/
MDN browser-compat-data|Structured compatibility data for programmatic checks, tooling, and deeper browser-version detail.|https://github.com/mdn/browser-compat-data
Modern CSS|A curated reference for modern CSS features, emerging platform capabilities, practical snippets, and current browser-support context.|https://modern-css.com
:::

### Technology and tooling sources

The web edition combines Markdown content, a Python content-generation step, SvelteKit for the chapter interface, Node.js for the build toolchain, Highlight.js for code presentation, and static-site output for deployment. The examples also cross into email development and server-side languages, so this section records the documentation used to keep those references grounded. ChatGPT, Claude, and Hermes are listed as AI-assisted research and editorial tools; their documentation describes the tools, not the CSS standards themselves.

:::source-cards
Can I Email|Email-client support tables for HTML and CSS features, used when the book discusses email-safe fallbacks and email rendering.|https://www.caniemail.com/
Markdown documentation|The CommonMark specification and reference syntax used to structure this book’s source manuscript and generated content.|https://spec.commonmark.org/current/
Svelte and SvelteKit|Component and application documentation for the Svelte-based chapter interface and static-site workflow.|https://svelte.dev/docs
TypeScript|Language and tooling documentation for typed JavaScript examples and CSS-adjacent API integrations.|https://www.typescriptlang.org/docs/
Node.js|Runtime and API documentation for the JavaScript build environment and content tooling around the book.|https://nodejs.org/docs/latest/api/
PHP|Official language documentation for the server-side CSS and web-platform integration examples.|https://www.php.net/docs.php
Python|Language and standard-library documentation for the content-generation and automation examples.|https://docs.python.org/3/
MJML|Email markup documentation for responsive email structures that compile to client-friendly HTML.|https://documentation.mjml.io/
ChatGPT documentation|Official OpenAI help and product documentation for the AI-assisted research, drafting, and editorial workflow used during production.|https://help.openai.com/en/collections/3742473-chatgpt
Claude documentation|Anthropic documentation for AI-assisted analysis, drafting, and review workflows used during production.|https://docs.claude.com/
Hermes documentation|Nous Research documentation for the Hermes Agent tooling used as part of the broader local research and automation environment.|https://hermes-agent.nousresearch.com/docs
:::
